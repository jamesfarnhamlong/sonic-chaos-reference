**Finish the authentic playable game first; close important ROM-fidelity issues second; add optional PC convenience third; extras last.** Deliver related fixes together: **one evidence preflight, one meaningful implementation batch, one private source-only Package A (B only if necessary), one compact 348×196 Windows acceptance, one direct-child commit and FINAL ZIP**. Stop after each milestone for Chief/Manager decision. No automatic Q4 launch.

**Source parent for ALL future candidates** is Q3-P1 [`7476affc`](https://github.com/jamesfarnhamlong/SonicChaos_POC/commit/7476affc6ed7626dabf69b446cdab0c9c3d7492e), not Q2-P1 or historical main. Research topic branches may remain unmerged into Research `main`; do not confuse them with the POC implementation head. User must supply private ROM/assets to local agents; cloud agents cannot see local `<local Windows Sonic Chaos workspace>` paths.

### Where to spend the remaining credits

1. **One concentrated M0/M1 research commission** to reconcile archives AND produce an implementable Tails/frontend evidence contract, rather than a chain of tiny sprite tasks. First reconcile this drafted trio against live Windows root AGENTS; do not perform another huge historical regression sweep.
2. **One sizeable Tails implementation candidate**, not per-character-animation ZIPs. If missing ROM frames block progression, finish authentic extraction rather than replacing them with inherited temp animation.
3. **One frontend cutover** only after Tails can play. Original title/character choice must never mask that the original Sonic campaign is already complete.
4. **One audio contract/dispatcher programme** using existing AUDIO-A0 previews and Research AUDIO-1B; approve the exact fidelity tier before loading dozens of files. Prefer a pilot plus substantive full-library package over numerous sound-effect one-offs.
5. Re-rank deferred bugs by **visible impact, reproducibility, ROM evidence, confidence, regression risk, credits**, then bundle related safe corrections. Known mild quirks can be parked.

## Safety, test and archive gates for every implementation group

- **Preflight:** exact accepted parent SHA, branch/worktree clean, source assets available locally, historical source contracts read. Existing Q3 private PNG/sound restoration checked before loading `.yyp`. Protect every accepted SHA and archive.
- **Scope and evidence:** clear implemented/deferred list; canonical 256 source-model comparisons where relevant, 348 source/Windows adapters explicit. No inventions, generic clamps, counterfeit assets, Tails movement assumptions or unverified audio files.
- **Verification:** meaningful focused assertions plus adjacent risk-based paired regressions and unchanged raw failure identities. Retain SS5 camera-X 256 raw FAIL and obsolete THZ3 boss-clear FAIL in ledger; never call 16 PASS / 2 FAIL “all green.” No routine full 18-act replay for a harmless sprite adjustment.
- **Candidate:** one `.yyp` source-only private package with full restored private resources, manifest and SHA-256. Candidate stays **unstaged, uncommitted and unpushed** until Chief's clear Windows approval.
- **Closure:** preserve accepted candidate runtime bytes, one direct-child commit and push; exact remote 0/0, clean tree, FINAL ZIP/checksum/resources and fresh-clone idempotent restoration. Manager alone reconciles root AGENTS; no automatic promotion of GitHub `main`.
- **Decision checkpoint:** Chief chooses next milestone after every acceptance; any unresolved/parked issue remains in `FIDELITY_REGISTER.md` without causing scope creep.
