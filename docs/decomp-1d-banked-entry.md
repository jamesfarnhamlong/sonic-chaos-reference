# DECOMP-1D: banked entry and control-flow recovery

Original feature branch `research/decomp-1d-banked-entry` (commit `3fcb719`) is preserved. This document describes the
integration branch `research/decomp-1d-integration`, based on Research `main` `fca02b7` (AUDIO-0 request ledger) with the
original work and the Manager review corrections applied. Nothing here touches the POC, root `AGENTS.md`, AUDIO-0,
EEZ or Special Stage work.

Evidence is regenerated by `python tools/decomp1d_banked_flow.py <ROM>` into `data/decomp1d/banked-flow.json`
(deterministic, no ROM bytes) and checked by `tests/test_decomp1d.py`.

## Outcome in one paragraph

From the original instructions, the `CALL $8000` at `$16E7` and `$1737` selects bank `$1C`, file `$70000`. The interrupt
handler's exit restoration, shadow integrity in its resident closure, and the bank-corrected instruction universe all
check out. **But assumption R1 is open**: the handler's banked callees contain three computed jumps whose index range the
code does not bound, so the closure cannot be shown to leave the mapper shadow alone. Per the review, the entry is
therefore **conditional**: the analysis is kept and tested, but it classifies nothing and registers nothing. The one
change to the accepted ledger is the audit correction F1 (a 32-byte table moves from CODE to DATA).

## Task 1: F1 corrected at the source

`tools/object_50.py` `ROUTINES` now states, for bank `$1C`:

| name | CPU | file | class |
|---|---|---|---|
| `placement_creator_loop` | `$8000-$80CA` | `$70000-$700CA` (203 bytes) | CODE |
| `placement_dispatch_table` | `$80CB-$80EA` | `$700CB-$700EA` (32 bytes) | DATA |
| `placement_create` | `$80EB-$813B` | `$700EB-$7013B` | CODE (unchanged) |

The table is not classified from its word pattern. `object_50.dispatch_table_proof` recomputes it from the ROM on every
run and aborts if it stops proving: confined descent from `$70000` reaches `LD HL,$80CB` at `$700BD`; the straight-line
run to `JP (HL)` at `$700CA` (nothing branches into it) ends in the word fetch `LD A,(HL) / INC HL / LD H,(HL) / LD L,A`;
16 consecutive words point at decodable code in the same bank (`$813F` once, `$813E` fifteen times); the 17th word
`$CDC5` is not a slot-2 address and its bytes `C5 CD` are the first instructions of the creator at `$700EB`. The proof is
stored under `proof` in the regenerated `data/rom-cache/thz3/object-50.json` (only the routine rows changed). The ledger
shows 0 contradictory pairs; `verify_cache.py` and the THZ3 tests were run (see Verification). The index range of the
dispatch (`A = 2 * (DE)`) is not bounded by the code, so only the sixteen words up to the first invalid word are claimed.

## Task 2: interrupt restoration hardened

`_walk_top_level` accepted any absolute load followed by `LD ($FFFF),A`. It now takes the shadow address and counts a
restoration only when the load is `LD A,($D12B)`. Synthetic regressions: `LD A,($D200)` (and `$D12A`/`$D12C`) followed by
`LD ($FFFF),A` is not a restoration and the handler is rejected; the genuine canonical `$060D-$0610` restoration still
holds and the exits `$0626`/`$0687` remain clean.

## Task 3: bank-corrected instruction universe

The handler calls `$4000` at `$05E0`/`$05F6` with slot 1 = bank 2, and the reset path also remaps slot 1. DECOMP-1D's
entry-integrity checks now use `state_walk`, a mapper-state-aware walk from reset, IM 1 and NMI (slot banks tracked from
`LD A,n / LD (reg),A`, and a call to a recognised mapper setter sets slot 2). Results (`instruction_universe` in the JSON):

| | instructions | bytes |
|---|---:|---:|
| DECOMP-1B resident descent (legacy) | 9,214 | 18,642 |
| bank-corrected resident universe | 6,667 | 13,718 |
| only in legacy (reached through slot 1 mapped wrongly) | 2,560 | 4,950 |
| only in corrected | 13 | 26 |
| banked instructions also reached | 1,268 | |

**Neither universe has any CALL/JP/JR/DJNZ or non-inert 16-bit literal that enters the setter call or the banked call of
either established caller, so the changed universe introduces no new entry into the sequences.** DECOMP-1B's
`data/decomp1b/callers.json` is an unchanged historical milestone artifact; its `vector_reachability` figures (9,214 /
18,642) follow the legacy rule and overstate the bank-correct resident universe. No ledger claim depends on them (the
four recovered callers' entries and the camera/player/level-header chains remain reachable in the corrected walk; no
DECOMP-1C stub relies on the descent). The 1B and 1C generators still reproduce their committed outputs exactly.

## The bank proof (unchanged, now conditional)

```
$16E2  3E 1C        LD A,$1C            $1732  3E 1C        LD A,$1C
$16E4  CD 6F 1C     CALL $1C6F          $1734  CD 6F 1C     CALL $1C6F
$16E7  CD 00 80     CALL $8000          $1737  CD 00 80     CALL $8000
```

`$1C6F` is `LD ($D12B),A / LD ($FFFF),A / RET`: shadow first, then the slot-2 register, so an interrupt between the two
stores still leaves register and shadow equal. File offset = `bank * $4000 + (cpu - $8000)` = `$70000`. The CPU address
alone proves nothing: the handler's own `CALL $8000` at `$05C6` maps bank `$1D`. The interrupt model proves the NMI handler
mapper-neutral, the IM 1 exit contract (every `RET` leaves `$FFFF` equal to the shadow), no shadow store in the followed
closure, and no shadow-store byte pattern outside resident code.

## Task 4: R1, investigated and not discharged

`state_walk` from `$0038` follows the handler's banked callees under the banks it maps: `$850A` and `$8000` (bank `$1D`),
`$B45A` (bank `$0E`) and the two `CALL $4000` into the bank-2 sound driver. Followed: 2,872 instructions (1,787 resident,
1,085 banked), no undecodable byte, **no store to `$D12B`**, no store to `$D12A`, restart edge `$2492` -> `$0450` (DI / `LD SP`)
not followed because it discards the interrupted context. Open edges, all computed jumps:

| site (file) | CPU context | form |
|---|---|---|
| `$86E8` | bank-2 driver, `$46E8` | `LD HL,$46ED / ADD HL,BC / LD C,(HL) / INC HL / LD H,(HL) / LD L,C ... JP (HL)` |
| `$8137` | bank-2 driver, `$4137` | `LD HL,$4138 / CALL $441D ... JP (HL)` |
| `$74027` | bank `$1D`, `$8027` | `LD DE,$8028 / ADD HL,DE / LD E,(HL) / INC HL / LD D,(HL) / EX DE,HL / JP (HL)` |

Their indices come from RAM bytes, so the table extents are not bounded by the code. Guessing extents (a prototype followed
every consecutive valid-looking word) over-approximates into unrelated code and reaches the reset path, so no discharge
was claimed from it. Discharging R1 needs those three tables' index ranges (a narrow piece of the sound driver). Until
then:

* `prove_banked_call` returns status `conditional` (`open_conditions: ["R1"]`), not `supported`; only `supported` records
  feed seeds, reviews or the ledger. `conditional=True` exists for analysis and tests only.
* `rom_ledger.import_reviewed` refuses `banked_transfer`/`bank_table` seeds, and `verify_registered_regions` refuses any
  `banked_` region, while the entry is conditional (tested).
* **Deferred, not in the ledger:**
  * `banked_entry_70000` `$70000-$700CA` (203 bytes, 135 instructions): already independently CODE via the audit claim;
    recovering it would add source coverage only.
  * `banked_dispatch_7013E` `$7013E-$70145` (8 bytes): the only bytes the entry would newly classify. They stay UNKNOWN.
  * The reviewed claim `$7013E-$70146` and its seeds (`banked_transfer`, two `bank_table`).
  They are defined in `decomp1d_banked_flow.REGISTRY` and `recover.py` `DEFERRED`; `recover.py --include-deferred` writes
  their assembly, and with them registered `build_verify.py` reassembles the ROM byte for byte (115 regions, 14,199
  bytes; checked once on this branch, not committed).
* The eight bytes themselves: `$7013E` is a bare `RET` (words 1-15 of the table) and `$7013F` is a seven-byte trampoline
  (word 0) ending in an indirect `JP (HL)`. They are code, not data, if the entry is accepted; that determination is part
  of the conditional analysis.

### Recorded assumptions

| id | status | assumption |
|---|---|---|
| R1 | **OPEN** | the handler's banked callees leave the shadow unchanged: followed code has no shadow store; three computed jumps are not followed |
| R2 | recorded | register-addressed stores (`LD (HL),r`, `(IX+d)`, block moves) that alias `$FFFF` or the shadow are **not modelled and not ruled out**; only absolute stores are checked |
| R3 | recorded | slot 1 is bank 1 when the handler starts; other absolute `$FFFE`/`$FFFD` store patterns exist only in compressed, unclassified or undecoded bytes |
| R4 | recorded | standard Sega mapper semantics, corroborated by the ROM's own register use, not by an emulator trace |

Evidence tier: static ROM-derived control flow, not an execution trace.
