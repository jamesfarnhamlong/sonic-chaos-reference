# DECOMP-1D: banked entry and control-flow recovery

Branch `research/decomp-1d-banked-entry`, started from Research `main` `6874337` (DECOMP-1C merged).
Scope: prove, from the original ROM instructions only, which bank the `CALL $8000` in the gameplay frame update
reaches, use that proof for the bank-`$1C` routine at file `$70000`, and wire it into the review generator and the
ledger importer without weakening any earlier rule. No POC, root `AGENTS.md`, audit-cache or object-script work.

Everything below is regenerated by `python tools/decomp1d_banked_flow.py <ROM>` into
`data/decomp1d/banked-flow.json` (deterministic, no ROM bytes) and checked by `tests/test_decomp1d.py`.

## Phase 1: the bank context, derived from the ROM

Both callers are in the recovered `gameplay_frame_update` (`asm/recovered/gameplay_frame_update.asm`):

```
$16E2  3E 1C        LD A,$1C            $1732  3E 1C        LD A,$1C
$16E4  CD 6F 1C     CALL $1C6F          $1734  CD 6F 1C     CALL $1C6F
$16E7  CD 00 80     CALL $8000          $1737  CD 00 80     CALL $8000
```

1. **Selecting instruction:** `LD A,$1C` at `$16E2` / `$1732`, consumed by the routine at `$1C6F`.
2. **Mapper register:** `$1C6F` is exactly `32 2B D1` `LD ($D12B),A`, `32 FF FF` `LD ($FFFF),A`, `C9` `RET`.
   `$FFFF` is the Sega mapper's slot-2 bank register (slot 2 = CPU `$8000-$BFFF`); `$D12B` is the RAM shadow the
   engine keeps of it. The shadow is written *first*, so an interrupt between the two stores still leaves register
   and shadow equal.
3. **Valid at the call:** the `CALL $1C6F` returns to `$16E7`/`$1737` (the next instruction), so nothing executes
   between the register write and the banked call except an interrupt. Nothing in recovered or hardware-vector-reachable
   code branches to `$16E4`, `$16E7`, `$1734` or `$1737`, and no 16-bit literal equal to them sits in executable or
   unclassified bytes (the only matches, for `$1734`/`$1737`, are two words inside level block-mapping DATA at
   `$50B90`/`$50B7E`).
4. **Conversion:** file offset = `bank * $4000 + (cpu - $8000)` = `$1C * $4000 + 0` = `$70000`. This is the
   standard slot-2 rule already used by `rom_flow.cpu_address`.
5. **What could invalidate the mapping** (all modelled, see below): interrupts, the only asynchronous writers. Branches
   and intermediate calls cannot (there are none). The result `bank $1C, CPU $8000, file $70000` was re-derived; the
   brief's candidate was not assumed.

### Why the CPU address proves nothing

`CALL $8000` appears at three resident sites. The two frame-update sites map bank `$1C`; the interrupt handler's call at
`$05C6` maps bank `$1D` (`LD A,$1D` / `LD ($FFFF),A` at `$05C1`-`$05C5`, file `$74000`). Only the first pair is
supported; `$05C6` (and `$0584` -> `$850A` bank `$1D`, `$059F` -> `$B45A` bank `$0E`) are recorded as unresolved because
their callers are not byte-verified recovered code. Seeds and claims are keyed by file offset, never by CPU address
(`ambiguity` in the JSON; tested with synthetic images where one CPU address names two banks).

### Interrupt model (the only hazard)

The game runs with interrupts enabled (`EI` at `$062D` waits for the frame flag), so a vblank interrupt can land between
the register write and the banked call. The handler remaps slot 2 itself (`$0581`, `$059C`, `$05B8`, `$05C3`,
`$05DD`), so the proof needs the exit contract:

* **IM 1 exit contract:** every `RET` reachable from `$0038` leaves `$FFFF` equal to the shadow. The two exits
  (`$0626` after the tail `LD A,($D12B)` / `LD ($FFFF),A` at `$060D`-`$0610`, and `$0687` on the non-vblank path, which
  never writes the register) are checked with every `CALL` treated as an opaque remap.
* **Shadow integrity:** the handler's resident call closure (1,787 instructions, slot 1 tracked through its own remap
  at `$05D8`/`$060A`) contains no store to `$D12B`; no byte sequence anywhere in the ROM stores to `$D12B` outside
  resident code (15 sites, all below `$8000`). A `JP $0450` in `$2492` (DI / `LD SP,$DFF0`, the reset-button restart)
  discards the interrupted context and is not followed.
* **NMI** (pause, `$0066` -> `$06A8`) touches no mapper register or shadow.
* The cartridge control register `$FFFC` is only written with `0` in the reset path (`$0008`, `$0466`), so slot 2 is never
  RAM; slot 0 (`$FFFD`) is only written with `0` (`$000D`, `$046B`), so resident addresses are file offsets.

### Residual assumptions (recorded in the evidence and required by the importer)

| id | assumption |
|---|---|
| R1 | The banked routines the handler calls are not walked: `$850A`/`$8000` (bank `$1D`), `$B45A` (bank `$0E`) and the two `CALL $4000` with slot 1 = bank 2 (file `$8000`, the sound driver). They contain no direct shadow store, but could transfer into a resident routine that has one. |
| R2 | Register-addressed stores that alias `$FFFF` or the shadow are not modelled; only absolute stores are. |
| R3 | Slot 1 is bank 1 when the handler starts. Other absolute `$FFFE`/`$FFFD` store patterns exist only in compressed, unclassified or undecoded bytes. |
| R4 | Standard Sega mapper semantics (bank number modulo the 32 pages). Corroborated by the ROM's own use of the register, not by an emulator trace. |

This is static control-flow evidence, **not an execution trace**. R1 is the one that would need a recovered sound driver
to discharge.

## Phase 2: the generator

`tools/decomp1d_banked_flow.py` reports, per resident slot-2 transfer: physical caller, CPU target, the three-instruction
sequence, the setter proof (shape, shadow, register), the statically established mapper value, destination bank/file
offset, whether execution can be followed safely, and the exact reasons for any refusal. A site is supported only if
all of these hold: a `CALL` in a recovered code region; directly preceded by `LD A,n` and `CALL setter`; the setter
decodes to shadow-then-`$FFFF`-then-`RET`; `n < 32`; the call returns to the banked call; nothing can enter the sequence
midway; and the interrupt model holds. Everything else stays unresolved:

| reason | meaning |
|---|---|
| `no_bank_setup_before_call` | no `LD A,n` / `CALL setter` pair directly before the call (an instruction between them also fails) |
| `bank_value_not_an_immediate` | the bank is computed, not a constant |
| `callee_is_not_a_recognised_mapper_setter` | register stored before the shadow, no `RET`, or no RAM shadow |
| `bank_value_outside_the_rom` | bank >= 32 |
| `something_can_enter_the_sequence_midway` | a decoded branch to the setter call or banked call (a conflicting path), or an address literal that is not in independent non-code bytes |
| `caller_not_in_byte_verified_recovered_code`, `caller_not_in_resident_engine`, `not_a_direct_call`, `target_not_in_slot_2` | outside the rule |
| `nmi_handler_not_proven_mapper_neutral`, `irq_exit_contract_not_proven`, `shadow_store_or_unmodelled_edge_in_irq_closure`, `shadow_store_pattern_in_banked_rom` | the interrupt model failed |

`rom_flow.py` is unchanged: `resolve_target` still returns `None` for a resident site calling slot 2, and every
DECOMP-1A/1B/1C rule is untouched. The 101 slot-2 transfers made by code that itself runs in slot 2 are same-bank by the
existing rule and are not re-examined.

## Phase 3: bank `$1C` at `$70000`

Entry `$70000` is supported by the proof above. Confined descent from it fetches **every** byte of `$70000-$700CA`
(135 instructions, no undecodable byte), ends in the terminal `JP (HL)` at `$700CA`, touches no recovered DATA, and its
internal targets (`$70031`, `$70043`, `$70049`, `$700A9`) are instruction starts. Its exits are `$7013C` (six `JP cc`,
inside `object_placement_create`) and `$700EB` (`JR nz` at `$700B1`, the start of `object_placement_create`); the
`CALL $0329` at `$700EC` is the existing recovered creator's resident stub.

**The eight UNKNOWN bytes `$7013E-$70145` are CODE, not data.** The `JP (HL)` at `$700CA` is a table dispatch:
`LD HL,$80CB` at `$700BD` (CPU `$80CB` in bank `$1C` = file `$700CB`), an index added into `HL`, then the word fetch
`LD A,(HL) / INC HL / LD H,(HL) / LD L,A` and `JP (HL)`; nothing branches into that straight-line run. The table is
16 words, `$700CB-$700EA`: word 0 = `$813F`, words 1-15 = `$813E`. The word after it (`$CDC5`) is not a slot-2 address
and the bytes there (`C5 CD`) are the first instructions of the creator at `$700EB`, so the table ends exactly where
code resumes. The targets are `$7013F` (`EX DE,HL / INC HL / LD E,(HL) / INC HL / LD D,(HL) / EX DE,HL / JP (HL)`, 7
bytes) and `$7013E` (a bare `RET`). Together they are the eight bytes; every byte is reached, the run starts after a
terminal `RET` (`$7013D`) and ends in a terminal `JP (HL)`, and the final `JP (HL)` is an **indirect exit** reading a
handler word from the object record at `(HL+1..HL+2)`; it is not followed. Region `banked_dispatch_7013E` registers
them.

The table itself (32 bytes) is **not** registered: `data/rom-cache/thz3/object-50.json` `placement_creator_loop` is a
hash-verified CODE claim for `$70000-$700EA`, so a DATA region would make 32 bytes contested. The ledger therefore still
calls the table CODE. See finding F1. The index range of the dispatch is not proven (`A = 2 * (DE)` is not bounded in
the code); only the sixteen words up to the first invalid word are claimed.

No bank other than `$1C` was scanned, and no callee outside `$70000-$70146` was followed.

## Phase 4: ledger integration

* `decomp1a_review.build(..., banked_seeds=True)` adds the proven entry and the dispatch-table words as seeds, keyed by
  file offset. In the committed state the registered regions already classify the bytes (as for DECOMP-1B/1C), so the
  reviewed file is unchanged; with the regions set aside the same proof produces the reviewed claim `$7013E-$70146`
  (tested).
* `rom_ledger.import_reviewed` re-derives two new seed kinds from the ROM and rejects stale, contradictory or unsupported
  ones: `{"banked_transfer": {"caller","bank","cpu"}}` (the bank is re-derived, never trusted) and
  `{"bank_table": {"table","words","load_site","consumer","index"}}` (reached only from a supported entry).
* `rom_ledger.build_ledger` calls `decomp1d_banked_flow.verify_registered_regions` for every `banked_` region: it must be
  one of the two registered ranges, its entries must re-verify, and confined descent from them must fetch every byte,
  end terminal and touch no DATA. A stale or invented `banked_` region aborts the build.
* Original-game traces are not used anywhere; the evidence tier is static.

Historical evidence is unchanged: `decomp1b_callers.py` and `decomp1c_callbacks.py` call the review with
`banked_seeds=False` and `banked_` is added to DECOMP-1B's `LATER_PREFIXES`, which restores the pre-1D region set; their
committed outputs reproduce exactly (tested). These are the only edits to historical generators; each is one argument
or one prefix.

## Findings for review (nothing here is applied)

* **F1:** the audit claim `placement_creator_loop` (`$70000-$700EA`, CODE) contains the 16-word table `$700CB-$700EA`.
  Correct at the audit source after review (as DECOMP-1A did for the object-50 animation dispatcher).
* **F2:** DECOMP-1B's resident descent follows the interrupt handler's `CALL $4000` at `$05E0`/`$05F6` into bank-1 file
  `$4000`, but slot 1 holds bank 2 there. 1,227 instructions / 2,732 bytes of `vector_reachability` are reached only
  through those two edges. No ledger claim depends on them (every vector-chain entry the 1B regions use is reachable
  without them; no DECOMP-1C stub relies on the descent), so the committed 1B output is left as is.

* 22 audit clusters (1,545 UNKNOWN bytes) and the 46 unsupported JP stubs are untouched, as instructed.
