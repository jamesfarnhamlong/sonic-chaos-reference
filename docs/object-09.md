# THZ1 object type `$09`

Type `$09` is implementation-ready for THZ1. Machine-facing data continues to
use numeric type `$09`; the recovered behavior updates the ring counter and its
reachable graphics are a ring/sparkle family, but no guessed source label is
needed.

**RAW RECORD COUNT: 24**

**RUNTIME ENTITY COUNT: 24**

Every nine-byte placement creates exactly one object slot. No callback creates
children, expands a pattern, or converts one record into several collectibles.
Parameters divide those entities into 11 visible rotating collectibles and 13
invisible collectible triggers.

## Placement and initialization

The records are indices 14–21 and 37–52 at ROM `$70623..$70781`. All use flags,
aux0 and aux1 `$00`; parameters are `$00` × 11 and `$01` × 13. The generic
bank-`$1C` placement creator writes the record's coordinate, type, parameter and
occupancy token into one slot. Type `$09` never allocates another slot.

State table `$9BC8` (ROM `$31BC8`) has four states. Initialization at `$9C10`
requests state 1 for parameter `$00`. A nonzero parameter requests state 3 and
sets renderer-skip bit 7 in object `+$04`.

| State | Script | Presentation / callback |
|---:|---:|---|
| 0 | `$9BD0` | empty frame `$00`, initialization `$9C10` |
| 1 | `$9BD6` | rotating frames `$01,$02,$04,$03`, eight updates each, callback `$9C22` |
| 2 | `$9BE8` | frames `$05/$06` alternate eight four-update records; terminal callback sets type `$FE` |
| 3 | `$9C0A` | empty frame `$00`, callback `$9C3D` |

Mapping `$8C71` (ROM `$3CC71`) and static THZ1 tiles `$10-$22` supply frames
`$00-$06`.

## Interaction and effects

Both parameters use `$617E`: collection requires
`abs(object_x-player_x) < 12` and `abs(object_y-player_y) < 12`. Controlled
original calls prove 11 succeeds and 12 fails on either signed axis.

On collection the callbacks request sound `$BF`, call vector `$0347` to `$3138`,
and increment packed-BCD `$D29A` by one. They do not change the score bytes.
The placement token `+$3E` is cleared, deliberately detaching terminal cleanup
from the source occupancy byte.

- Parameter `$00`: visible rotating presentation; collection requests state 2,
  which displays a 32-update `$05/$06` sparkle before type `$FE` cleanup.
- Parameter `$01`: renderer-skip bit 7 and empty frame make it invisible. `$9C3D`
  tests only when global frame byte `$D12F` is even. Collection sets type `$FF`
  immediately, with no visible sparkle.

Uncollected objects outside the generic visibility lifetime become `$FE` while
retaining their placement token. `$5EF8` then clears occupancy, so returning can
recreate them. Collected objects clear the token first; occupancy remains set
and they do not respawn during the loaded act.

## Separate terrain-ring population

The 142 cached positions from layout blocks `$40-$43` are not generated by
type `$09`. Player top-probe handler `$753E` requires surface type 7, identifies
the layout block/quadrant through tables `$75DC..$760B`, changes the block,
creates its presentation effect, and increments the same ring counter. Type
`$09` callbacks never read a layout cell. Sharing `$D29A` does not merge the
source populations.

## Verification

`tools/thz1_object_09.py` reproduces all placements, states and controlled
fixtures in `data/rom-cache/thz1/object-09.json`. Tests cover all 24 records,
both parameters, strict overlap, even/odd hidden timing, packed-BCD effect,
32-update sparkle, off-screen cleanup and the separate 142-position population.

These are source and controlled-subroutine results, not a full SMS emulator
observation.
