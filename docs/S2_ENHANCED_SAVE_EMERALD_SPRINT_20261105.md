# Sonic Chaos — S2 Enhanced Data Select & Zone Progression
**5 November 2026 · Manager-san #10 · REVISED per Chief's explicit Sonic 3-style contract and two visual references · S2 GO**

## Binding Chief design — supersedes the first S2 proposal
**Chief's design is not a separate opt-in Saved Campaign mode.** In the unified frontend, after choosing **ENHANCED**, the existing `START GAME` entry leads through the accepted opening/title and then **directly to a Sonic 3-style five-slot DATA SELECT screen in place of the original Sonic/Tails character-choice screen**. **CLASSIC** keeps the original title → character selection and original campaign unchanged. There is **no Enhanced save-toggle/feature flag, no 'Saved Campaign' text row in Enhanced Options, no extra mode-choice screen, and no alternate parallel game executable**. Saved progression is an inherent part of Enhanced gameplay.

Chief supplied two Sonic 3-style Data Select image references in the management conversation (private user images; do not copy/repost any third-party copyrighted pixel artwork publicly). The intended language is **horizontal cards with a television preview, character portrait, zone preview and emeralds, a distinct completed-game image, and a visible deletion affordance**, not an elaborate text-driven file manager. Keep original game's visual character and controller support; reuse original GameMaker resources where appropriate, with accurate zone-specific previews rather than generic repeated art.

**Existing original OpenSonic five-slot UI is already present**, though disconnected:
- `ROM_menu_data_select`, `OBJ_menu_data_select`, `OBJ_menu_data_card_1` through `_5`, `OBJ_menu_data_button_del`, related form/zone/emerald sprites. `OBJ_menu_data_select/Alarm_0.gml` already creates exactly five cards; `Step_0.gml` uses left/right to change slot, up/down to change **individual act**, and confirm to launch. The inherited `SCR_load_game` / `SCR_save_game` and `saveGameN.ini` are intentionally removed from natural campaign use and **MUST NOT be reactivated**. **Investigate/reuse only presentation layout/visual assets and relevant input patterns**; replace unsafe legacy gameplay/save logic completely or isolate it from live mode.
- Accepted game `chaos_acts()` lists **18 acts**, six zones in order **THZ → GPZ → SEZ (Sleeping Egg; Chief wrote 'SLZ' in example) → MGHZ → AQZ → EEZ**, three acts per zone. There are genuine 1-based act indexes but this **saved-progress system tracks a zone frontier**, not the current act.
- `chaos_run_new_game(character, room)` owns the canonical reset for Sonic/Tails; `global.chaosCollectedFlags` is authentic Emerald ownership. Do not save or reconstruct a running actor/room state. `global.chaoEmerald` and inherited legacy save variables are not canonical.
- `chaos_ss_entry_eligible` allows Special Stages only for Sonic and refuses entry when first five bits are complete; `chaos_ss_selected_zone` derives stages from collected bits and `chaos_ss1_goal_phase` sets the actual earned bit. `SCR_chaos_eez_boss` sets the **sixth bit (32)** on the **Sonic 5-emerald final-boss route**, yielding six total (bits 0..5) only when the full route is earned; Tails has its distinct ending. *This is not a universal award on any EEZ3 clear.* A save needs only five Special Stage bits plus completion marker; the displayed sixth icon can be **derived when Sonic has all five and the full ending is achieved**. Never falsely display six for a Sonic partial-ending clear or for Tails.

## End-user Data Select behaviour (authoritative)
### New empty slot
- Present **five horizontal slots**, left/right cycling/wrapping among them. Selected empty card shows Sonic/Tails portrait.
- **Up/Down toggles Sonic versus Tails** on **empty/uncreated slot only**. One confirm creates a valid slot with **locked character, frontier THZ, zero Emeralds, `completed=false`** and starts canonical **THZ Act 1**. No second original character-selection screen in Enhanced. Do not write the slot until a deliberate confirmation, not merely moving selection.
- Once created, character is **permanently locked for that slot**; the only reset is an explicit **DELETE/WIPE** with confirmation.

### Existing unfinished slot
- Left/right selects slot. Up/down cycles **unlocked ZONES**, never individual Acts. The television preview shows the selected zone, with its actual zone-specific image; visible permanent high-water progression remains stored separately from the temporary currently highlighted zone.
- A **normal selected-zone launch always starts ACT 1 of that zone**, regardless of where the last physical session stopped. During continuous play, the existing campaign may naturally progress through Acts 1→2→3 and onward; when later loading after quit/death or replay, **there is no mid-act/mid-zone resume and no life/Continue restoration**.
- When a real **zone's Act 3 clear** is committed after results (boss/end-of-zone chain), save the **next zone as highest unlocked/frontier**, and update that slot's default highlighted/TV zone to the newly unlocked zone. Do not promote on an Act 1/2 clear, level entry, results preview, pause or developer/debug shortcut. **EEZ3 has special final boss/ending handoff**; use authentic completion instead of synthetic next-zone index.
- Example: Sonic reaches **MGHZ Act 2** and quits. Stored frontier is **MGHZ**, which offers THZ1, GPZ1, **SEZ1** (Chief's typed 'SLZ1' appears to refer to Sleeping Egg Zone) and MGHZ1. The default selection may highlight MGHZ1; up/down lets the player choose any unlocked zone. **No loss of high-water mark through replay.**
- Replaying an earlier zone does not erase previously earned progress, duplicate Emerald awards, reopen consumed Special Stages or grant an unearned next-zone unlock. Following replayed stages can use the ordinary original transitions, but new persistence only ever advances the stored frontier when an actually newly earned zone boundary is crossed.

### Emeralds and completion
- **Sonic:** persist only earned five Special Stage bits (masked 0..4) and any justified claimed-entry status required by source rules. Award after confirmed successful Special Stage path/return; no advancement on failure. Preserve Sonic's actual ring-triggered entry rules. Once each of five Emeralds is earned, the corresponding Special Stage cannot be re-earned; if the original existing selector already excludes it, use canonical behavior rather than introducing another intrusive gate. A consumed zone-specific special-entry rule is optional only if it can be shown safe and consistent; don't mistakenly block all future Stage chances because of a failed attempt.
- **Tails:** stores **no Emeralds**, receives no Special Stage earnings or emerald icons, cannot switch character to Sonic without wiping the slot. Do not invent emerald stages for Tails.
- **Game completion:** on authentic EEZ3 final clear/ending handoff, store `completed=true`, display the Chief-requested **special completed-game TV graphic**, and unlock selection of **any of the 18 acts**, not merely six zone starters. Keep character lock. A Sonic full-emerald completion displays **six emeralds in the TV/card** (the five saved rewards plus the derived final boss sixth); a Sonic partial completion must NOT falsely show six. Tails completion has a completed graphic but no Emeralds. Make the all-act selection discoverable with simple visual act indicator, without adding a Save Mode label to Enhanced Options.
- If the Chief later revises what should be shown for a partial Sonic ending or how the 'complete' stage selector should work, adjust only the small display policy, not the entire save schema.

### Slot deletion and control
- Include a visible **WIPE/DELETE** affordance, reachable by keyboard and physical controller; require two-step confirmation so accidental pad input cannot destroy a save. Empty slot deletion does nothing. Clear data and selected-card presentation immediately after successful deletion. ESC/pad B returns safely to the original title/menu and preserves other slots.
- Do not require new persistent saves for original lives, Continue count, score, rings, powerups, zone Act 2/3 position, camera, actors, boss state or ongoing native soundtrack. Each launch uses the canonical character start resources; no separate game-core state owner.

## Storage contract — intentionally small
One independent **versioned and validated** five-slot Enhanced store (or five independently versioned slot files) containing only:
1. schema/version and integrity/recovery metadata;
2. `occupied`, locked `character` (Sonic or Tails);
3. `frontier_zone` (THZ..EEZ, never act index) and `completed` flag;
4. Sonic-only **5-bit claimed Emerald mask**, with any extra anti-duplicate marker only if source proves needed.

The current cursor/selected zone is **ephemeral UI**, not the saved progression. For post-completion all-act browsing, cursor may select act individually; before completion it selects **zones only**. Do not persist lives/continues/score midlevel progress. Do **not** reuse legacy `saveGameN.ini`, original `settings.ini` or Classic's natural-run state. Protect absent, corrupt, truncated, newer-version, failed-write and interrupted-save cases; use an atomic-ish/backup rollback appropriate to GameMaker Windows. Failed writes must be visible and leave recoverable data; never silently corrupt/overwrite another slot.

## Implementation architecture / S1 protection
- Branch from **exact locally verified accepted S1** `56c767e8b4f0f73c41f2d8ec41ca471d7a90e746` once clean/recoverable. S1's display features and existing defaults remain unchanged; final graphical default choices are explicitly deferred until endgame (possible fullscreen integer-fit and shader interdependencies).
- Reuse original Data Select presentation assets when genuinely suitable, but **do not activate the old legacy save/load/act-select behaviour**. Implement one new Enhanced-only UI/controller and one namespaced persistence/progression owner, no duplicate game core or developer shortcut. Do not copy pixels from Chief's reference screenshots.
- Redirect only committed Enhanced original-title character-choice destination → Data Select. Classic still follows title → original Sonic/Tails choice. **No new Enhanced Options row, label or opt-in flag.** The save screen replaces character choice, not the existing SEGA splash/title.
- If canonical progress/emerald/ending events require guarded observation hooks in previously frozen GML on a **new S2 successor branch**, those are permitted when they are no-ops outside committed Enhanced and preserve original event order, audio, timing, camera, collisions and Classic results. Capture exact diff/proof. Do not modify/tag-rewrite frozen Classic.
- The phase of the actual save write matters: prefer a reliably *committed* zone clear/earned Emerald/ending boundary, and guard replay. Do not insert premature disk writes at mere goal contact. A death/Game Over and a reload should never grant unearned progress.
- Existing Save/Resume/Score/Continue paths from old OpenSonic are not evidence of correct new saved-campaign behaviour. Use fresh robust storage with one active slot identity and clear session reset.

## Substantial S2 sprint execution and combined gate
**S2 is ONE development sprint.** Designer should research source callbacks/visual resources, implement all slot UI and save logic, iteratively resolve routine issues, verify progression, and deliver **one integrated Chief-facing Windows candidate**. Cheap source/state checks during coding, native test compiles as needed for GameMaker IO/render APIs, but no separate package/Chief checks for each option or card. Stop early only for a genuine unresolvable architecture or major game-design ambiguity.

Combined integration:
- Five-slot navigation/portrait cycle/delete confirmation, wrap/debounce, pad and keyboard; existing Classic choice unaffected.
- Empty create starts THZ1, locks Sonic/Tails, persists only minimal fields. Select a different slot and launch at correct act/zone; restart app and recover data.
- Complete Acts1/2 without advancing saved frontier, **clear Act3 and verify next zone TV/current default**, quit during Act2 then reload selected zone Act1; replay earlier zones, confirm frontier never decreases.
- Both characters and all six zone types including last EEZ completion, the distinct Sonic full/partial endings and Tails ending; correct 18-act selection only for `completed` slot.
- Sonic five Special Stage successful/failed/duplicate/replay cases, full final sixth derived graphic only on correct completion, Tails never earns emeralds. Avoid over-testing by controlled deterministic states with transparent artificial-setup labels.
- Corrupt slot, interrupted write, unreadable/older/newer version and recovery; no effect on `settings.ini`/old `saveGameN.ini`/Classic and no debug/test path writes.
- Native audio request/PSG/PCM and core/zone transition invariants compare to accepted S1 for matched gameplay. Existing visual Sharp/Integer/CRT switches remain unchanged and at least a basic ON/OFF combination smoke passes. Do not commission whole Sonic/Tails playthrough.
- Package one private Windows ZIP, complete source ZIP, actual-resolution UI visual comparisons (empty Sonic/Tails, occupied different zone TVs, five Emeralds, full Sonic six+completion, Sonic partial, Tails completion), source diff, deterministic evidence, SHA-256 and H: backup/recovery receipt. One **short combined Chief check**: make one Sonic/Tails slot, see portrait/lock/TV, use one controlled early-zone progress checkpoint if available, quit/reload, wipe second slot, verify Classic title/choice remains unchanged.
