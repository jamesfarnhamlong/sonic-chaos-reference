## Coherent S2 workstreams
### A. Design the saved-campaign contract using real current code
1. Map the exact original original run front door, result/next-act commit point, five Special Stage rewards/failed-retry/return paths, sixth Emerald/final boss/ending handoff, Tails eligibility and Continue/Game Over/quit transitions. Build an event/ownership diagram, including which events are *earned* versus presentation-only, and the correct safe moment to persist.
2. Decide an **initial small number of visible save slots** (3–5 reasonable candidates; the inherited `global.memoryCards=5` is *not* an automatic chosen contract), one character per slot, New/Continue/Replay/Delete with safe confirmation. Document conservative defaults and how 100% completion is defined. If character/emerald semantics fundamentally conflict with owner's stated expectations or cannot be resolved from source, isolate the issue and request one substantive Chief design decision; do not stall for routine menu aesthetics.
3. The full save contract must be understandable **in the UI**: no mystery hidden nested Options menu or developer shortcut. **E0's "START GAME" remains the bottom entry** on Enhanced Options; launch a distinct, clear Saved Campaign choice/slot screen only in Enhanced. Classic selection enters the original cinematic/title/character choice without any saved-mode prompting or file I/O. Support physical pad and keyboard throughout. Avoid bypassing the original gameplay/character choice without designing an explicit, appropriate Enhanced-only path.

### B. Implement persistence that will not lose progress
1. Use a **separate new namespaced saved-campaign format** (not existing legacy `saveGameN.ini`, `settings.ini` or original natural-run globals). Include file schema version and per-slot character, next progression act, completed/unlocked/replayable act bitset, Sonic/Tails eligibility as established from code, five claimed Special Stages/emerald bitmask, final-sixth award state, campaign completion/ending flag, and any narrowly needed counters. Avoid saving every volatile midlevel actor/physics state.
2. Bound all read values and validate version and identity; handle missing/corrupt/truncated/unwritable files without crashing the game or overwriting a valid prior save. Implement atomic-ish temp/replace and backup/fallback using **documented GameMaker file APIs actually available in installed LTS**; do not promise POSIX atomicity on Windows. Provide a rollback/recovery test, invalid input fail-closed, and explicit owner notification when a slot couldn't be written. Use isolated test storage for verifiers, never mutate Chief's actual save folders.
3. A saved mode should **resume at a safe act boundary** with canonical `chaos_run_new_game` initialization then apply approved persistent fields at the correct lifecycle point; do not restore an arbitrary active enemy/boss/player/palette snapshot. Review lives/score/continues policies against Chief's intended Sonic3-style save behaviour; if not agreed, choose a modest documented launch default that doesn't grant free progression or break ending rules.
4. Persist **completed gameplay events**, not just a goal touch or selected room: credit ordinary acts only at committed clear/next-act transitions (respect results timing and score), Special Stage emeralds only once after confirmed successful return, final Emerald only at authentic final Robotnik/boss completion, and completion only on the correct ending handoff. Add guarded transition hooks in relevant **successor-branch** GML only as required; preserve original Classic/all-OFF state, audio and frame timings. No developer launch can unlock or write a normal save.

### C. Unlocked stages, replay, results and visual UI
1. Completed slot **unlocks/replays already cleared acts** with a clear `PROGRESS`/stage-select screen. Never allow a new save to jump into unearned stages or earn the same Emerald repeatedly by revisiting a previously completed Special Stage. A replay cannot silently move next progression backward, duplicate a final reward or lose already-earned achievements. Define how a replay affects score/Continues and implement one consistent policy.
2. Provide a simple visible current slot summary—Sonic/Tails, last unlocked act/zone, collected Emeralds, completion indicator—using original-style font/sprites and existing art only. No artwork overhaul or AI-synthesized original sprites.
3. Preserve current original results, title, Continue, special-stage and endings cadence. Save status presentation must not intrude on Classic or perturb the native audio/timing owner. Do not add an extra audio driver or hidden keyboard teleport.
4. If a save is corrupt or full, give readable status/error and a safe return/new file path; do not create a trapped/black menu. Retain accepted renderer lifecycle during Pause/results/death, Classic unchanged and Enhanced graphical toggles unaffected.
