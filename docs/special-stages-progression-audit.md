# Special Stages SS-A5 — progression, rewards, persistence and closure

Unmerged research on `research/special-stages-canonical`. Machine package `data/rom-cache/special-stages/progression.json` (+ `art-approval.json` for the visual package); tools `tools/ss_progression.py`, `tools/ss_art_boards.py`; tests `tests/test_ss_progression.py`.
Evidence: CONTROLLED (original `$178F`/`$187B`/`$1E:$9489` run in sequence), EMULATED (whole-game traces), BYTE-VERIFIED (reader/writer scan).

## 1. Stage selection and order

`$D2CC` bits 0..4 record completed stages; `$187B` picks zone `8 + (consecutive set bits from bit 0, max 4)`. Driven through the original routines (`progression.json`):

| Outcomes of successive entries | Zones entered |
|---|---|
| all succeed | 8, 9, 10, 11, 12, then **refused**, refused (final bits `$1F`) |
| succeed, fail, fail, succeed... | 8, **9, 9, 9**, 10, 11, 12, refused |
| fail every time | 8, 8, 8 (the sequence cannot advance past a failed stage) |

So the stage order is strictly 1..5; a failed stage is *offered again* at the next 100-ring entry; completed stages are never repeated; after five completions `$178F` refuses entry for good. The 100th ring still awards the extra life (`$3104`) and wraps the ring counter to 0 even when entry is refused.

## 2. Persistent flags and what persists

- `$D2CC` (completion bits) and `$D2C3` (continues, low 7 bits) live outside the cleared ranges. Writers in the whole ROM: `$2A1F` (new-game reset, called only from the title-start routine at `$04D4`), `$1E:$94A7` (goal ring), `$1E:$BB69` (sixth bit). Readers: `$179A` (entry gate), `$1883` (selector), `$18F4` (ending selector), `$33F1` (results emerald icons), `$1E:$BB21/$BB64`. There is **no save, password or battery path**; progression exists only in RAM.
- EMULATED persistence (start `$D2CC=$07`): death with lives left -> `$07` kept; game over with no continue (passes through zone **7**, the Game Over screen — *not* a Special Stage) -> `$07` kept until a new game; game over with continues -> continue used (`$D2C3` low bits -1, bit 7 set), lives restored to 3, **score cleared, `$D2CC` kept**.
- Starting a new game from the title runs `$2A00`, which clears `$D2CC` (CONTROLLED: `$1F -> $00`), rings and score.

## 3. Reward model (linkage proven, not named from appearance)

Success is exactly the `$31` callback (SS-A4): `D2CC |= bit`, `D2C3 = (D2C3+1) & $7F` (a **continue**; bit 7 cleared), `D2A6 = D2BF << 8`, `D2CD = $FF`. The results screen (`$32F9`, card chosen by `$D2CD != 0`) draws the continue icons from `D2C3 & $7F` (`$337F`, up to 8) and the emerald icons from `$D2CC` (`$33F1`); a continue is consumed at `$1491`. The tally (`$2D08`) converts stage rings to score at +10 raw units per ring and the remaining time at **+1 raw unit per iteration, 100 iterations per remaining second** (original `$2D28/$2EFB`; EMULATED SS1 success with 58 s left added exactly 5800 raw units in 5800 `$262F` calls). The results card prints `RING n x 100` and `TIME t x 10` (EMULATED frames); the displayed score is consistent with raw units x 10, but the HUD's final-digit presentation was not traced. For Sonic (`$D2C8 == 1`) one extra continue is granted whenever the thousands digit of the score becomes 0 or 5 (`$266F..$26BD`), i.e. every 5,000 raw units; this fired in the 58-second success (`D2C3` 1 -> 2 at raw 5000). Failure grants nothing; the tally uses stage rings and the previous `D2A6` (zero in a fresh game).

## 4. Final stage and the ending

Completing SS5 has no special stage-exit behavior. Its only lasting effect is `$D2CC == $1F`: all later entries are refused. The completion bits feed the ending through the final-zone `$61` object (see `docs/eez-boss-endgame-audit.md`, `data/rom-cache/eez/boss-game-flags-31.json`): with `$D2CC == $1F`, Sonic's `$61` chain sets bit 5 (`$20`) and `D293 = $50`; the ending selector `$18ED` takes the full ending only when `$D2CC & $3F == $3F`, a partial ending for fewer flags, another path for other characters. Only Sonic can enter a stage (`$D2C8 == 1`).

## 5. Return to normal gameplay

Always the next act (`$D298 += 1`) via the act-clear sequence, after the results card and tally; rings, timer and active power-ups do not carry. Canonical quirk (SS-A1): from act index 2 the return loads act index 3 = the next zone's act 0 data under the old zone number. Failure costs no life and offers no retry.

## 6. Visual package

New-composition boards are generated by `tools/ss_art_boards.py` into the ignored `build/ss-approval/` and indexed by `data/rom-cache/special-stages/art-approval.json` (**all PENDING James; nothing inherited**): five maps (SS1/SS4 in parts), two terrain block sets (outdoor art stream `$64000`, pipe-interior stream `$65590`), the five goal-ring colourways (blue, yellow-orange, green, grey, magenta; exact `$31` mapping frames 1-3 over each stage's own VRAM), monitor-icon animation for parameters 4/5/6 (EMULATED crops), goal ring in situ, and the Special Stage results cards (success/failure). `$2F` and `$26` compositions that are pixel-identical to approved MGHZ/THZ art are recorded in `dedup` and not re-submitted; shared tube art uses new SS streams so it *is* submitted. No redraws, no invented animation.
