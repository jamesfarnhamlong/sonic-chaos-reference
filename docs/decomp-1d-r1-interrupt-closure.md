# DECOMP-1D-R1: interrupt dispatch closure

Branch `research/decomp-1d-r1-interrupt-closure`, based on Research `main` `eec2a0d` (DECOMP-1D integration). `main` had
not advanced. Nothing here touches `SonicChaos_POC`, the root `AGENTS.md`, DECOMP-1B/1C artifacts, the accepted ledger,
`asm/recovered`, EEZ or Special Stage data. The ROM was only read locally (SHA-256 verified before use) and is not in any
file of this change.

Evidence is regenerated by `python tools/decomp1d_r1_closure.py <ROM>` into `data/decomp1d/r1-interrupt-closure.json`
(deterministic, no ROM payload, 0.26 MB) and checked by `tests/test_decomp1d_r1.py`.

## Verdict

**R1 is PARTIALLY CLOSED.** It is not closed and it is not open.

* The three dispatchers named in DECOMP-1D were re-derived from the ROM. Each one was reduced from "index not bounded" to an
  exact, ROM-computed domain and destination map. They are not equal in strength.
* **Site A (ROM `$086E8`, the bank-2 sound-driver flag dispatcher) is proven.** Its code bounds the index to the 32 flag
  values `$E0-$FF`; 30 of the 32 table words are valid handlers; the other two (`$EF`, `$F1`) point into a data table at
  CPU `$48AC`. A walk of every sound stream the original driver can start shows neither flag is ever a command, and a
  controlled run of all 68 requests agrees with that walk. The official walk therefore follows A's 30 handlers and both
  pushed return addresses.
* **Sites B (`$08137`) and C (`$74027`) remain partial.** Their guards admit index values that read bytes which are not
  table words, and no ROM-derived bound excludes those values. The unresolved facts are stated exactly (section
  "What closure still needs").
* Four more computed jumps sit behind site C. Three of them (masked, 2-4 words) are proven; one (zone-indexed) is partial.
* **No followed destination, supported or not, stores to `$D12B`, `$D12A` or their RAM mirror** (8-bit and 16-bit
  encodings), and no newly reachable code stores to a mapper register. This is a proof of absence for the followed absolute
  stores only; register-addressed writes remain R2.
* The accepted ledger is unchanged. The deferred DECOMP-1D regions stay deferred (see "Implications").

## The contract

The question: can an interrupt after the bank-`$1C` selection (`LD A,$1C / CALL $1C6F`, then `CALL $8000` at `$16E7` and
`$1737`) leave the slot-2 register or its shadow `$D12B` in a state that changes the destination of the following call?

* `$1C6F` stores the shadow first, then `$FFFF`. An interrupt between the two stores sees register and shadow differ by
  one store at most; the handler's exit rewrites the register from the shadow.
* The IM 1 vector (`$0038`) is `DI / PUSH AF / IN A,($BF) / RLCA / JP C,$04E2` (vblank) else `JP $0650` (line interrupt,
  no mapper access). The vblank path restores both registers from RAM before it returns: `LD A,($D12A) / LD ($FFFE),A`
  at `$0607` and `LD A,($D12B) / LD ($FFFF),A` at `$060D` (store at `$0610`), then `POP`s, `EI`, `RET` at `$0626`; the other
  exit is the line-interrupt `RET` at `$0687`. Both exits are clean in the top-level exit model.
* NMI (`$0066`, 16 instructions) stores to no mapper register or shadow and makes no call.
* Exceptional restart: `JP $0450` (`DI / LD SP`, reached at `$2492`) discards the interrupted context. It is not followed;
  no new restart edge appears in the conditional closure (`restart_paths` in the evidence).
* The register is preserved if (a) the handler returns normally, so the exit restoration runs, and (b) nothing in the
  closure changes `$D12B`. (b) is what the dispatchers decide.

Out of scope but worth knowing: resident code reached by the handler writes `$FFFF` directly (`$0D38`, `$0D42`, `$24AB`)
without updating the shadow. The exit restoration repairs those writes for the handler itself; this task makes no claim
about interrupt timing in other code that writes `$FFFF` directly.

## Method

For a `JP (HL)` the proof does not look at neighbouring data.

1. **Dominating region.** Starting at the jump, walk backwards over every known predecessor (fall-through or decoded
   transfer) while no decoded `LD rr,nn` names the instruction. Instructions with an outside predecessor become *starts*:
   they are entered with arbitrary register state. Every execution that reaches the jump therefore enters the region only
   at a start. A start is kept only if it can be decided; an undecidable start is replaced by its successors and the region
   is re-closed (`entry_integrity.collapsed_starts` lists each one with the reason). A region whose entry cannot be closed
   is not proven. Hardware vectors and walk roots count as having an outside predecessor, and a region with no way in is
   a failure, never "unreachable".
2. **Exact execution.** From each start, `tools/z80_exec.py` runs the code concretely for all 256 values of `A`: either
   with `A` holding the value, or with the first load of an unknown byte into `A` taking it (so a RAM/stream byte is
   enumerated exactly). It models 8-bit wrap and carry exactly (`ADD A,A` of `$90` is `$20` with carry), conditional
   branches on exactly computed flags, ROM reads through the bank mapping, `PUSH`/`CALL`. Anything it cannot decide (an
   unknown flag, a RAM read used as an address, a mapper write, an unsupported instruction) is reported as undecided and
   fails the proof; a value is only "left the chain" when a known, taken branch leaves the region.
3. **Destination map.** For each value that reaches the jump, `HL` and the table word that supplied it are exact. The
   footprint is the set of words read. Nothing is inferred from neighbouring words.
4. **Support.** A destination is *supported* when a confined descent from it reaches no undecodable byte and no transfer
   into RAM, it is not in bytes the ledger (or the proven sound-stream parse) classifies as non-code, and the word that
   named it lies in the table region (below the lowest valid destination: a table cannot extend into the code it points to).
   This is a necessary condition, not proof that the bytes are a routine: it is what the walker's own `invalid` and open-edge
   checks then test again.
5. **Dispatcher status.** *proven* when no unsupported value is in the code-defined domain, or an independent ROM-derived
   data proof removes every unsupported value from it; *partial* when some are; *unproven* when none is supported.
6. **Two walks.** The **official** walk follows only proven dispatchers. The **conditional** walk also follows the supported
   destinations of partial ones (their jump stays an open edge, `partial_dispatch`). Nothing from the conditional walk is
   promoted; it exists to ask whether the supported destinations could hurt the shadow if the missing facts were proved.

## The three task sites

### A: ROM `$086E8` (bank 2, CPU `$46E8`) — proven

```
$46D5 LD HL,$46E9 / $46D8 PUSH HL / $46D9 SUB $E0 / LD HL,$46ED / ADD A,A / LD C,A / LD B,0 / ADD HL,BC
LD C,(HL) / INC HL / LD H,(HL) / LD L,C / $46E7 LD A,(DE) / $46E8 JP (HL)
```

* **Calculation.** Word index `(flag - $E0) * 2`, table at CPU `$46ED`. `ADD A,A` is 8-bit; the carry is dropped. The table
  abuts its first handler: 32 words `$46ED-$472C`, handlers from `$472D`.
* **Index source.** `A` is the flag byte `LD A,(DE)` fetches from a music or sound-effect stream: `$434F` for tone channels,
  `$465A` for the noise channel. Both enter with `CP $E0 / JP NC,$46D5` (`$8353`) and `CP $E0 / JR NC,$466B` (`$865E`), the
  second via `LD HL,$4671 / JP $46D8`, which skips the `LD HL,$46E9` and returns to `$4671`. Two guards, two pushed returns
  (`$46E9`, `$4671`); the proof found both and followed both.
* **Range from the code.** `$E0-$FF`. Entry integrity: 37 region instructions, 5 starts, every start's unknown load is
  `LD A,(DE)`.
* **Destinations.** 30 of 32 words are valid handlers (21 distinct) in `$472D-$48A3`; see the list below.
* **The two bad words.** `$EF` and `$F1` (words at `$470B`, `$470F`) both hold `$48AC`, the first byte of a data table
  `C0 48 CC 48 D9 48 ...`. Executing it is `RET NZ / LD C,B / CALL Z,$D948`: a call into RAM.
* **Why the data proof is needed and what it is.** Whether `$EF`/`$F1` can be a command is a question about stream data.
  1. The original request arbitration (`$407F`) and dispatch (`$4119`) are run for every request id `$81-$C4` on a plain Z80
     core with the ROM mapped as the driver sees it. Every active channel's stream pointer and flag byte are read back:
     164 stream-start states, 164 distinct pointers. The channel base (only `$DED0` runs the noise routine `$464A`) selects
     the grammar and flag bit 3 the initial note mode. The tool reads no header by hand.
  2. Each flag handler was run on random operands (six fills, identical result) to measure how many operand bytes it
     consumes: `$E0` 5, `$E7` 0, `$F0` 4, most 1. The five control flags and the note-mode toggle are identified by code
     bytes (`SIGNATURES`), and the tool fails if the ROM does not match: stop `$F2`, jump `$F6`, loop `$F7`, call `$F8`,
     return `$F9`, mode `$FD`.
  3. Every stream is walked token by token (duration, one-byte setting, note + optional duration, three-byte custom note in
     mode 3, flag + operands), following jumps, loops and calls. 11,309 tone and 2,399 noise token positions, 19,946 stream
     bytes, **no problems**. The flags found as commands are `$E0 $E1 $E6 $E7 $F0 $F2 $F3 $F5 $F6 $F7 $F8 $F9 $FB $FD`.
     `$EF` and `$F1` never occur as commands.
  4. Cross-check: the real driver, run for up to 4,000 updates per request (12 loop forever), fetches only token positions
     the static walk reached and dispatches exactly those 14 flags.

  The walk also yields 72 intervals of stream bytes. They classify the target of site B's word `$D3` as non-code.
* **Status: proven**, with the data proof as its second premise. If the stream proof is wrong, A is partial again; the test
  `test_site_a_is_proven_only_through_the_stream_data` makes that dependence explicit.

### B: ROM `$08137` (bank 2, CPU `$4137`) — partial

```
$4119 LD A,($DE03) / BIT 7,A / JP Z,$43E5 / CP $A0 / JR C,$4168 / CP $C5 / JP C,$41A7 / CP $D4 / JP NC,$43E5
$412F SUB $D0 / LD HL,$4138 / CALL $441D / $4137 JP (HL)          ; $441D: LD C,A / LD B,0 / ADD HL,BC / ADD HL,BC / word fetch
```

* **Calculation.** `HL = word at $4138 + 2*((A - $D0) & $FF)`, zero-extended (`$441D` does `LD B,0`).
* **Index source.** `$DE03`, the current sound request. It is loaded from the mailbox by the arbitration routine at `$407F`
  (`LD (IY),A`, `IY = $DE03`), initialised to `$80` (`$41A3`), and cleared by the reset fill at `$43E5`.
* **Range from the code.** `$C5-$D3`: 15 values. Not `$D0-$D3` as AUDIO-0 recorded: the guard `CP $C5 / JP C,$41A7` lets
  `$C5-$CF` fall through to the `SUB $D0`, which turns them into `$F5-$FF`.
* **Table.** Three words `$4138 $413A $413C` → `$4140 $43E5 $4150`. `$413E/$413F` are `00 70`; code starts at `$4140`.
  * `$D0 $D1 $D2` are supported.
  * `$D3` reads `$7000`, a position inside song data (the stream walk proves those bytes are stream data): unsupported.
  * `$C5-$CF` read `$4322-$4336`, which are code bytes (`JR NC,$8335`, ...): they name `$1130 $80FE $0A28 $CBDD $EE00 $C9E1
    $1A13 $DD18 $18AF $26DA $18FF`. Unsupported.
* **Status: partial.** Supported destinations (followed only in the conditional walk): `$4140`, `$43E5`, `$4150`.
* **How far the request sources were bounded** (`supporting_evidence`): all 84 immediate `LD ($DE04),A` encodings load
  values in `$00 $82-$C4 $F8` (none in `$C5-$D3`; all are AUDIO-0 ledger ids); the script route (`FF 06 xx`, handler
  `$67D5` is sub-command 6) cannot name an out-of-table id because the ROM contains 238 `FF 06` pairs and none is followed by
  `$C5-$D3`; the boss-clear route loads `$89` or `$97`; the zone music table has 39 entries in
  `{$81 $83 $8F $90 $91 $92 $93 $95}`. `$DE05/$DE06` have no writer except the clear in the arbitration loop.
  Two routes are **not** bounded: the zone-music read `$18B2` (the index is `3*$D297 + $D298` in 8 bits; bytes past the
  39th are code, which contains values in `$C5-$D3`), and the sound-test value `$D2BF` (clamped to `$80-$C4`/`$FF` at
  `$0BBA-$0BCC`, but the loop's closure has three unresolved computed jumps, so another writer of `$D2BF` is not excluded).

### C: ROM `$74027` (bank `$1D`, CPU `$8027`) — partial

```
$8018 LD A,(IY) / ADD A,A / LD L,A / LD H,0 / LD DE,$8028 / ADD HL,DE / LD E,(HL) / INC HL / LD D,(HL) / EX DE,HL / $8027 JP (HL)
```

* **Calculation / source.** `(IY+0)` is the state byte of one of four 8-byte slot records at `$D452 + 8k` (`LD IY,$D452` at
  `$8005`, `B=4`, `CALL $8018` per record). `ADD A,A` drops its carry: values `v` and `v+128` read the same word.
* **Range from the code.** All 256 values, 128 distinct words.
* **Table.** 21 words `$8028-$8051`; the first handler (`RET`) starts at `$8052`. Supported values: `$00-$14` and `$80-$94`.
  Everything else reads code bytes.
* **Who writes the byte.** The level loader `$2A4F` copies four type bytes from a record chosen through two pointer tables
  indexed by `$D297` (zone) and `$D298` (act): 16 first-level words, nine records, types `{0 1 2 3 4 5 6 8 11 12 13 14}`.
  The allocator `$1CD3` writes `C` into the first free slot; its direct callers pass `C` = 16 (`$30B7`) and 7, 9 (seven calls
  through the kernel vector `$0374`). Zeroing at `$1CEC`/`$1D06`. **No instruction in the bank-`$1D` closure writes
  `(IY+0)`.**
* **Status: partial.** Supported destinations: the 16 distinct valid handlers.

### Behind site C: four more computed jumps (all inside the handlers C selects)

| ROM | CPU | handler | index | words | status |
|---|---|---|---|---:|---|
| `$7407F` | `$807F` | type 1 (`$8053`) | `(IY+2) & 3` | 4 (`$8080`) | proven |
| `$741F1` | `$81F1` | type 5 (`$81BF`) | `((zone*2 + b)*2) & $FF`, `b = (IY+2) & 1` | 12 (`$81F2-$8209`) | partial |
| `$74285` | `$8285` | type 6 (`$8259`) | `(IY+2) & 1` | 2 (`$8286`) | proven |
| `$744CB` | `$84CB` | type 12 (`$84A4`) | `(IY+2) & 3` | 4 (`$84CC`) | proven |

The zone-indexed jump needs `zone <= 5` while a slot of type 5 runs: the table has six zones × two acts, and type 5 occurs only
in the records of zones 2, 4 and 5.

## What closure still needs

Each lemma below, if proved from the ROM, turns the named dispatcher proven. None is assumed.

* **B, zone/act.** Whenever `$18A0` runs, `3*$D297 + $D298 <= 38`. The writers of `$D297` are nine absolute stores including
  `INC` at `$15D6` and table loads at `$0821`/`$2C55`; the bound is a program-flow invariant (the level-complete path runs only
  for zones 0-5), not a local property.
* **B, sound test.** `$D2BF` changes only at `$0B38`/`$0BCC` while the sound-test loop runs. Its closure (719 instructions)
  ends in three unresolved computed jumps in the object engine.
* **C, record fetch.** `$D297 <= 15` and `$D298 <= 2` when `$2A4F` runs (the same zone/act invariant).
* **C, allocator.** Every caller of `$1CD3` passes `C <= 20`. The 8 enumerated call sites do; `$0374` is also a kernel-vector
  entry that callback stubs can reach with an unknown `C`.
* **`$741F1`, zone type.** While a type-5 slot runs, `$D297 <= 5`.

## Residual assumptions

| id | status | |
|---|---|---|
| R1 | **PARTIALLY CLOSED** | as above |
| R2 | open | register-addressed stores that alias `$FFFC-$FFFF` or the shadow/mirror are counted, not excluded |
| R3 | open | slot 1 is bank 1 when the handler starts; the dispatch proofs assume the handler's own mappings (sound driver: slot 1 = bank 2, slot 2 = bank 3; `$8000` routine: slot 2 = bank `$1D`) |
| R4 | open | standard Sega mapper semantics; no emulator or hardware trace of the mapper |
| R5 | new | the instruction universe is the code discovered by the reset/IM 1/NMI walk, the recovered regions and the resolved dispatchers; operand-position literals in unclassified bytes (counts per proof in `entry_integrity`) are not shown inert. A proven region is only as complete as that universe, and sites B and C are still open computed jumps |
| S1 | new | stack discipline: `RET` returns to its caller; handlers that deliberately unwind (`POP HL / POP HL / RET`) are not modelled |

R1 being closed within a bounded static model would still leave R2-R5, so the banked-entry proof could not be called
unconditionally safe on this evidence even then.

## Tests, reproducibility, limitations

* `python -m unittest tests.test_decomp1d_r1`: 103 tests (about 45 s with the ROM; 34 need it and skip without it). Synthetic
  images cover: exact tables behind masks and compare guards; off-by-one guards; unguarded wrap (`v` and `v+128`); valid-looking
  words past the extent; second entries with weaker guards; decoded literals naming a block; bank-correct file offsets for the same
  CPU address in two banks and for slot 1; data domains that promote, do not promote, or do not apply; destinations that write
  `$D12B`, its mirror, `$D12A`, `$FFFF` or `$FFFE` (8- and 16-bit); register-addressed writes counted; unresolved computed
  jumps blocking closure; nested dispatchers; the stream grammar (operands hiding `$EF`, optional durations, mode 3, loops,
  calls); the executor's carry/wrap/flag/bank behaviour, differentially against the pinned Z80 core for every value of `A`
over fifteen ALU programs and six `ADD HL,DE` cases; table bounds that contradict themselves (a destination inside its own
table, in RAM, or undecodable); loops through a dispatcher; a jump no value can reach; and a partial dispatcher never becoming
a complete edge. ROM tests pin
  the three sites, the stream proof, the request-source facts and the regenerated evidence.
* Existing suites re-run: `tests.test_decomp1d`, `1c`, `1b`, `1a`, `test_rom_ledger` pass; `rom_ledger.py --check` passes
  (156,887 classified, 13,988 recovered assembly bytes in 113 regions, 367,401 UNKNOWN, 0 contested); the DECOMP-1A/1B/1C/1D
  generators and `recover.py` reproduce their committed outputs byte for byte; WLA-DX (built from source in the cloud
  session) reassembles the ROM byte-identically from the 113 regions.
* `tools/decomp1d_banked_flow.py` changed only by an additive `dispatch` argument and a `cpu_at` result key on `state_walk`;
  `data/decomp1d/banked-flow.json` is byte-identical.
* Limits: static evidence plus controlled Z80 runs; no PSG/VDP behaviour; the stream proof depends on the driver's token grammar
  as measured, cross-checked by a bounded run; the support test is a necessary condition; R2-R5 and S1 stand.

## Implications for the deferred DECOMP-1D assembly

`banked_entry_70000` and `banked_dispatch_7013E` stay deferred. R1 is not closed, so the entry remains `conditional`; this change
does not modify the registry, `recover.py`, the recovery manifest or the ledger. Even if the lemmas above were proved, R2-R5
would remain, so promotion would be a decision about accepted conditions, not about missing proof. Recommended order if
Manager wants to pursue it: (1) prove the zone/act invariant, which discharges B's table route, C's record fetch and the
zone-indexed jump together; (2) resolve the object-engine computed jumps that keep the sound-test closure open; (3) bound the
`$0374` kernel-vector callers. A separate promotion review is premature before (1)-(3).
