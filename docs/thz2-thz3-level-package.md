# THZ2 / THZ3 canonical level package

Research only. ROM: Sonic Chaos (Europe) v1.2, SHA-256
`eabc8db59746714262d2f91a921d054823484349099a9fcd04fd6e84a1fee607` (verified; never committed).
`SonicChaos_POC` was not touched. THZ1 is the control fixture and is regenerated by the same pipeline.

Machine-readable output (authoritative): `data/rom-cache/levels/{thz1,thz2,thz3}/{layout,rings,objects,assets,manifest}.json`
and `data/rom-cache/levels/object-census.json`. PNG maps are research aids under `build/` (git-ignored, reproducible).

Evidence classes: DECODED DATA, BYTE-VERIFIED ASSEMBLY, SOURCE-TRACED, CONTROLLED ROUTINE RESULT,
HISTORICAL REFERENCE ONLY, UNRESOLVED.

## 1. How the offsets were verified (nothing taken from historical notes)

Every act is described by the engine's own tables, disassembled and consumed by the generic tool
`tools/level_package.py`:

| Table | File offset | Consumer | Evidence |
|---|---|---|---|
| act header table (zone -> act -> 22-byte record) | `$5082` | loader `$4FDC..$5081` | BYTE-VERIFIED ASSEMBLY |
| player start table | `$4E98` | `$4E57` | BYTE-VERIFIED ASSEMBLY |
| object-list pointers | bank `$1C` / CPU `$8546` (`$70546`) | placement creator at `$70000` | BYTE-VERIFIED ASSEMBLY |
| level art entries (7 bytes each) | `$7CED + 7*(zone*3+act)` | `$78E1` | BYTE-VERIFIED ASSEMBLY |
| palette selectors | `$7F3C + 2*(zone*3+act)` | `$794F` | BYTE-VERIFIED ASSEMBLY |

The 22-byte act header contains: block-mapping bank/pointer, layout bank/pointer, map width, `-width`,
three camera-limit words, and the row-offset table pointer. THZ1/2/3 records are at `$050EA`, `$05100`, `$05116`.

| | THZ1 | THZ2 | THZ3 |
|---|---|---|---|
| layout (file / bank:CPU) | `$48000` / `12:$8000` | `$48BA9` / `12:$8BA9` | `$49815` / `12:$9815` |
| layout stream end (exclusive) | `$48BA9` | `$49815` | `$49C25` |
| object list (file / bank:CPU) | `$705AE` / `1C:$85AE` | `$7078C` / `1C:$878C` | `$708FE` / `1C:$88FE` |
| object terminator byte | `$7078B` | `$708FD` | `$70958` |
| block mapping | `$44000` (`11:$8000`) | same | same |
| primary tile stream | `$40F9E` (`10:$8F9E`, VRAM `$1800`) | same | same |
| background / sprite palette | `$3B79D` (idx `$15`) / `$3B6AD` (idx `$06`) | same | same |

All historical leads (Sonic Retro table: object lists, layouts, dimensions, mapping, tileset, palettes) **agree
with the ROM-derived values**; each act's `manifest.json` records the field-by-field comparison. The layout
streams are contiguous (THZ1 -> THZ2 -> THZ3 -> GPZ1 `$49C25`), and each object list starts one byte after the
previous list's `$FF` terminator.

The art entries and palette selectors of all three THZ acts are identical, so THZ1/2/3 share one 251-tile primary
stream, the same six supplemental streams, and one VRAM image (`d26902fa9fc1...`, identical hash in all three).

## 2. Dimensions and layout decode

* Width = header word +6 (128 / 128 / 80); height = terminated cell count / width (32 / 32 / 16).
* Independent consistency checks recorded per act (all true): `-width` field, row-offset-table stride equals width,
  header word +18 + 240 = pixel height, header word +16 = (width-8)*32, header word +10 = 7*width. The last three
  are observed arithmetic relations, not proven field meanings.
* Block = 32x32 px (4x4 tile entries). THZ2 = 4096x1024 px, THZ3 = 2560x512 px.
* Stream format (loader `$4DC4..$4DFA`): a non-`$FF` byte is one cell; `$FF value count` repeats; `count = 0` ends.
* **Runtime bound:** the loader writes at most 4095 cells (`$C001..$CFFF`). THZ1 and THZ2 stream 4096 cells, so
  the final cell (index 4095) is never written; `layout.json` keeps the encoded row and lists it under
  `runtime_bound.unwritten_cell_indices`. THZ3 (1280 cells) is unaffected. No ring is lost to this bound.
* `layout.json` also gives block usage (mapping addresses, tile ids, collision surface type, palette/priority bits).

## 3. Terrain-derived rings

Derived from shared ROM tables, not assumed: handler `$753E` collects only where the block's collision surface
type is 7, using the quadrant presence table `$75DC` (quadrant = x-bit-4 + 2*y-bit-4). The ROM defines **six**
ring blocks, `$40..$45`:

| Block | Quadrants |
|---|---|
| `$40` | top-left, top-right |
| `$41` | bottom-left, bottom-right |
| `$42` / `$43` | top-left / top-right |
| `$44` / `$45` | bottom-left / bottom-right |

`$44/$45` are not used in any of the three layouts. The presence table matches the block art exactly (each ring
fills bbox `[1,0,14,15]` of its 16x16 quadrant), which justifies the quadrant-centre coordinate
`world = cell*32 + quadrant origin + 8` (the convention THZ1 already used; THZ1's committed 142 positions are reproduced exactly).
Each ring records act, cell index, cell x/y, block id, quadrant, quadrant origin and offset.

## 4. Type `$09` and totals

`objects.json` keeps every `$09` record as an object; `rings.json` adds a derived view with `source_class`
`terrain`, `object_09_visible`, `object_09_hidden`. Initialization `$09C10` was run in the controlled Z80
harness: parameter `$00` -> state 1, renderer visible; parameter `$01` -> state 3, renderer-skip bit 7
(CONTROLLED ROUTINE RESULT). Only parameters `$00` and `$01` occur in THZ1/2/3, so the THZ1 interpretation carries
over from the shared code; no other value was interpreted. Collection is the shared `abs(dx)<12 && abs(dy)<12` test.

| | THZ1 | THZ2 | THZ3 |
|---|---|---|---|
| dimensions (cells) | 128x32 | 128x32 | 80x16 |
| terrain rings | 142 | 133 | 6 |
| type-`$09` raw records | 24 | 13 | 3 |
| visible `$09` (param `$00`) | 11 | 9 | 3 |
| hidden `$09` (param `$01`) | 13 | 4 | 0 |
| visible total (terrain + visible `$09`) | 153 | 142 | 9 |
| raw objects | 53 | 41 | 10 |
| unique object types | 8 | 7 | 5 |
| new types vs THZ1 | - | 0 | 1 (`$50`) |

## 5. Object census (numeric ids; counts THZ1 / THZ2 / THZ3)

Records carry index (1-based, as in the THZ1 cache), ROM offset, bank/CPU, raw bytes, type, world X/Y
(`stored - 256`), flags, parameter, aux0, aux1. Bytes 5-8 are raw type-specific fields; their names follow the THZ1 census.

| Type | Counts | Class | Notes |
|---|---|---|---|
| `$09` | 24 / 13 / 3 | A | ring family; parameters `$00/$01` only |
| `$10` | 5 / 5 / 1 | A | new parameter values in THZ2 (`$03`) and THZ3 (`$01`) vs THZ1 placements |
| `$18` | 1 / 1 / 0 | B | goal sign; completion behaviour partial |
| `$1B` | 4 / 0 / 1 | B | |
| `$21` | 6 / 5 / 0 | A | |
| `$26` | 4 / 10 / 4 | B | one new parameter `$88` in THZ2 (record 26) |
| `$27` | 3 / 4 / 0 | A, D | THZ1 behaviour complete; semantic identity unresolved |
| `$28` | 6 / 3 / 0 | B | new aux1 values `$13`/`$19`, parameter `$84` group as in THZ1 |
| `$50` | 0 / 0 / 1 | C, D | **new**, THZ3 record 1 at (1936,238); identity unresolved |

A = covered by THZ1 research, B = present in THZ1 but incomplete, C = new to THZ2/3, D = identity unresolved.
Classes come from `data/rom-cache/thz1/object-census.json`. Per-variant novelty is in `object-census.json`
(`new_variants_vs_thz1`); a new *placement variant* of a covered type is a follow-up, not a new type.

## 6. Graphics / asset manifest

`assets.json` (per act): level art entry, streams, VRAM load table, palettes with CRAM bytes, block mapping; and per
placed type the mapping pointer (`$3C000 + 2*type`, bank `$0F`), state-table pointer (`$65BA`), statically
reachable frames, frame origins/pieces/bounds, tile ids, and placement aux bases. Types already extracted for THZ1
(`$09 $10 $18 $1B $21 $26 $27 $28`) reuse the same mapping and tile bases; reference sheets are rendered from the
act VRAM (plus the verified `$18` dynamic list) into `build/level-object-sheets/`.

Type `$50`: mapping `$94C6` (file `$3D4C6`), 7 frame pointers, 19 states at bank `$1E:$958B`, frames `$00-$06`
reachable, state 4 unresolved by the static tracer. Its **art source is UNRESOLVED**: a trial render from the static
VRAM shows other objects' tiles, so geometry only is exported and no image is produced.

## 7. Presentation

The mapped-object model (`R8 = -(camera_x+1)`, `R9 = (camera_y+17) mod 224`, SAT Y+1) is recorded in each manifest
as a reference only. Canonical anchors (`world_x/y`) and mapping geometry (`assets.json`) are stored unmodified and separately;
no GameMaker offset is baked in.

## 8. Reference maps

Native scale, lossless PNG, drawn only from decoded ROM tiles: `build/level-maps/<act>/<act>_{terrain,rings,objects,combined}.png`
(image height = level height + 30 px legend band). Renderer assumptions (documented in `tools/level_maps.py`): palette-1
tile attribute selects the sprite palette half; colour 0 is the backdrop; priority bits, animation and parallax are not modelled;
the unwritten final THZ1/THZ2 cell is left as backdrop. Markers: yellow circle = terrain ring, cyan diamond = visible `$09`,
magenta boxed X = hidden `$09`, white crosshair + `$NN` label = object anchor. PNGs are not versioned (reproducible; 4096x1054 files).

## 9. Unresolved / follow-ups

* Type `$50`: identity, behaviour, art source (likely act-specific dynamic load), state 4 script.
* New parameter variants: `$10` (`$03`/`$01`), `$26` (`$88`), `$28` aux values; run the THZ1 behaviour studies against them.
* `$18` completion behaviour, `$1B/$26/$28` lifetime work (inherited from THZ1).
* Player-start record words are exported raw; their field meanings are not named.
* Runtime palette animation and tile priority are not modelled in the maps.

## 10. Regeneration

```bash
export SONIC_CHAOS_ROM="/path/to/Sonic Chaos (Europe).sms"
python tools/level_export.py "$SONIC_CHAOS_ROM" --output data/rom-cache/levels \
    --maps build/level-maps --sheets build/level-object-sheets
python -m unittest tests.test_level_package
```

Tooling: `tools/level_package.py` (act descriptors, decoders), `tools/level_export.py` (JSON, control fixture, census),
`tools/level_maps.py` (PNG maps). It reuses `thz1_object_assets.py`, `thz1_animation_reach.py`,
`thz1_type18_dynamic_graphics.py`, `thz1_object_09.py`. Requires Python 3.10+ and `requirements.txt`.
