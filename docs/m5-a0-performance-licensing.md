# M5-A0 performance, storage and licensing

## Measured offline cost

The exact receipts are in `data/m5-a0/results.json`. A five-run C stress benchmark generates 1,200 ticks/run from one active tone+noise state; it is synthetic arithmetic load, not a complete song. Median 26.0196µs per 735-sample tick, about 640.54× realtime. Python/ctypes single-block median 25.9001µs and p99 48.3190µs on this machine. The instrumented Python emitter+ctypes+state-recording candidate took 0.280989 seconds over all 5,587 ticks (0.209099 seconds for the 4,200-tick loop case). The adapter DLL is 164,864 bytes in this build; no final extension size is implied. These are offline C/process measurements, not GameMaker throughput, GUI frame timing or human audio acceptance. They do not predict all machines or worst-case native scheduling.

Measured fixed adapter/core state is 6,304 bytes (includes 735 stereo32-bit staging entries); the unchanged resampler eagerly allocates 1,773,440 bytes, one second of stereo chip-rate scratch. Eight mono queue blocks add 11,760 bytes. Whole Python/NumPy proof process peak working set was 367,521,792 bytes, including private intent programs, original Z80 oracle, captured rows and analysis arrays; it is not the native backend allocation. The measurement deliberately reports both. A later allocation change to the one-second resampler buffer needs its own validation; no such optimization was made here.

At 221,680 native chip updates/second there are about 3,694.67 updates per driver tick. Each update decrements four counters, potentially toggles three tones/advances noise, mixes four amplitudes, and contributes to resampling. That is approximately 886,720 counter updates/second before mixing/resampling/host overhead. Multiplication by a guessed GML slowdown factor is not a measurement. Native C appears affordable; an extension is the recommended experiment, not proven mandatory.

Proposed next isolated native gate: use a standalone minimal GameMaker test project with the same eight-buffer lifecycle and synthetic/non-ROM event controls, outside the accepted POC. Test sustained 60 Hz 735-frame production, 30 Hz double-tick scheduling, delayed callbacks, pause/resume, scene flush, repeated Stop and shutdown. Record VM and YYC separately where available, native allocated bytes, CPU/block latency distribution, underruns and audio-buffer lifetime. A proposed target is p99 synthesis+transfer below 1 ms/tick with zero sustained queue underruns and no in-flight deletion; this is a future acceptance proposal, not a relaxed fidelity threshold or an achieved result. Do not start it automatically.

## Storage evidence, not a full-library estimate

The reused/extended intrinsic bank currently occupies 13,979,564 bytes as verbose private JSON, 277,485 bytes under deflate. It contains 68 indexed programs with uneven coverage, not the complete original library in production form. The 4,200-tick accepted loop-boundary control needs 34,518 bytes in a diagnosticu16-count+ordered-bytes transport versus 6,174,000 bytes of mono 16-bit PCM for that duration (about 179× smaller). These bytes were counted from independently emitted events, not used to bypass context scheduling. Control streams and envelopes will need structured private representation, not merely raw combined logs.

This demonstrates material reduction on the measured sample, but cannot justify a precise replacement size for the proposed 1.1–2.1GiB PCM library. Do not multiply an arbitrary compression ratio over every song. Final size needs a complete private event decoder/export coverage audit and measured packed production records. The synthesizer binary and fixed state are small compared with PCM, while accepted M4 assets still contribute their existing size. No full catalogue export or long $90/$91/$8C rendering was undertaken.

## File-specific license assessment

The pinned `emu/cores/sn76496.c` declares BSD-3-Clause and Nicola Salmoria as copyright holder, retaining historical contributor notices. The official source still shows that declaration: [upstream PSG source](https://raw.githubusercontent.com/ValleyBell/libvgm/master/emu/cores/sn76496.c). Reuse must preserve copyright/contributor notices, the conditions and disclaimer; binary redistribution must include them in accompanying materials, and contributor names cannot imply endorsement. [BSD-3-Clause terms](https://opensource.org/license/bsd-3-clause).

This does **not** grant the same license to all of libvgm or MAME. Fourteen transitively included source/header files were hashed at the pinned commit; resampler, logging and several headers do not declare a license in their own headers, and the pinned checkout supplies no project LICENSE file. The required source files are clean; the prior environment-based core-selection patch affects only the unrelated `vgm2wav.cpp` reference wrapper and was not changed. See `source-license-audit.json` for exact paths/hashes.

The maintainer confirms unfinished module licensing in the [upstream licensing discussion](https://github.com/ValleyBell/libvgm/issues/129); an intended future BSD-like license is not a present redistribution grant. The [earlier discussion](https://github.com/ValleyBell/libvgm/issues/43) also concerns mixed core provenance. Therefore this locally compiled proof is **not a redistribution-cleared extension**. No upstream source or binary was copied into public Research. The public adapter includes the separately supplied sources at build time and retains their notices unchanged in local source storage.

Before a distributable extension, either establish applicable permission for the exact resampler/logging/header dependencies or independently implement/document replacements and re-run fidelity checks. A small independently written PSG is also possible, but would require a new independent chip-verification effort; this proof does not supply one. Do not assume linking the entire libvgm or MAME distribution is required or licensed by the one BSD core. No upstream permission request or other message was sent.

Original ROM-derived note/envelope/event programs and all audio remain private. Later playback can use converted private event records plus a small emitter/synthesizer; it must not require an original ROM, regenerating Z80 binary or full SMS emulator. Copyright status of source code does not authorize publication of original musical data.
