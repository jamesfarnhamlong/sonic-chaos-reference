# M5-A0 stateful PSG architecture specification

**Conditional feasibility demonstrated.** The proposed boundary is an independently scheduled original-driver emission model → one continuously advancing PSG and resampler → exactly 735 signed 16-bit mono samples per 60 Hz tick. Keep the accepted 3,546,893 Hz PAL clock and 44,100 Hz output. This is an offline integration prototype, not GameMaker code or a complete sound driver.

## Responsibilities and inputs

`tools/m5a0/backend.py:candidate` accepts only an intrinsic private program bank, an external request/fade schedule and a native adapter path. It advances the accepted P0R model itself. No combined original execution trace, oracle PCM or reference register timeline is an input. In the proof the candidate finishes before original Z80 execution is instantiated. A separate reference-only adapter records counter/LFSR snapshots from the original writes for diagnostic comparison; it never drives candidate playback.

The model retains mailbox/priority/slot/read/envelope ordering and emits bytes. Each tick sends the complete ordered byte vector, then generates 735 samples from one instance. Request boundaries never recreate the chip or reset its oscillator phase. No attenuation/gating is applied outside the PSG, no finite source lifetime is needed, and physically held output follows the chip until a real write changes it. Repeated equal noise-control bytes remain distinct reset events. Tone2 changes alter the noise period while preserving elapsed counter/LFSR history.

Original note/duration/tempo/loop programs, channel initialization, envelope programs and request semantics are still required. The 68 indexed audio programs present in the bank are **not 68 fully decoded production programs**: most inherited entries contain older metadata, while the P0R emission-intent coverage is explicitly limited. This proof extends only solo $81 from 1,400 to 4,200 ticks for the previously captured near-loop control. Other programs keep their inherited coverage. Exceeding coverage raises an error. Do not fill missing events with silence, infer an infinite loop from a finite capture, or ship the original ROM/Z80 sound region.

An eventual private event representation can use a per-channel intrinsic program with relative driver tick, opcode/operand, envelope epoch/steps and control-flow state. Its runtime emitter must reproduce context-dependent reads and latch writes; a full-mix prelogged VGM for every request pair is not that representation. The adapter API accepts a count and byte vector. A simple diagnostic transport uses u16 count followed by bytes per tick; all bytes share the original accepted tick boundary and retain order. This maintains M4's tick cadence; it is not Z80-cycle-timed PSG writing.

## Persistent synthesis state

The thin C adapter includes the pinned MAME SN76496 core unchanged. It retains three tone periods/counters/output bits, noise period/counter/output and 16-bit LFSR, all eight registers, last selected register, effective volumes, clock divider and resampler position/last-sample memory. The Sega configuration uses taps 9, width 16, divider 8, Sega zero-period rules, equal stereo lanes and the accepted reference polarity. One lane supplies mono output. PSG native update rate is floor(3,546,893/16) = 221,680 Hz, preserving the accepted MAME pipeline rather than introducing a new fractional-clock policy.

The reference player's single-PSG base gain 0x80 is normalized to 0x200. The adapter uses that documented constant, not a fitted per-case scale. PCM clamps once to signed 16-bit at output. Initial MAME attenuation registers read 0 although effective amplitudes are 0 until initialized; P0R's logical default is off 15. These unwritten defaults are counted separately. Full original-versus-model physical/register comparisons remain unchanged; all registers explicitly written to the chip must agree. The first trial exposed this distinction rather than demonstrating a new original-driver fault.

`write(bytes)` changes registers without generating samples; `render(n≤735)` advances the same instance; diagnostic `state()` exposes counters/LFSR, register values and resampler position; `free()` releases it. This is a proof ABI, not a stable extension API. It has no SMS CPU, ROM reader, VGM parser, filesystem playback or embedded sound program. The build links only the selected PSG, resampler and logging source, not all of MAME/libvgm.

## GameMaker integration proposal — later authorization required

Keep the existing owner, 735-sample block cadence and eight 1,470-byte queue buffers. A later native call could accept the current ordered writes and fill an already allocated staging block; the owner copies/submits it through the accepted queue path. Callback completion only releases the matching queue/buffer generation and drains retired pools. It must never generate samples, advance driver state, access a freed chip, or perform file I/O. Detach handles before stopping/freeing queues. Keep native pointer lifetime under the one owner; do not let callbacks retain it.

Pause freezes driver tick, PSG/resampler and cursor, and pauses the queued voice; it must not render silent blocks while muted. Scene transitions alone do not recreate state: use explicit original requests/stops and the existing queue flush semantics. Generation-owned staging must not be reused until submission/copy completes. Retired audio buffers survive until their callbacks finish. Shutdown remains idempotent and prevents new production before native destruction.

Numeric $F8 is the priority-gated original driver command: apply its ordered frequency/off writes while keeping chip oscillator/LFSR state unless an actual PSG reset/control write changes it. It is not an unconditional chip reinitialization. The separate administrative PC Stop may flush the queue and clear driver/backend ownership as an explicit host operation; its subsequent fresh-start policy must be documented. Do not quietly substitute it for numeric $F8 or change accepted M4 behavior.

A narrow hybrid is recommended: accepted M4 opening/title/selection/THZ PCM remains byte-identical under its current owner; new content can later use stateful synthesis. Any handoff between the frozen PCM path and synthesis requires an explicit reset/state/queue policy and independent seam acceptance. Crossfades, double ownership and unproved reconstruction of M4 oscillator state are not proposed. This prototype validates all-synthesis sequences only, not a live hybrid seam.

Native GameMaker feasibility remains unmeasured. A GML implementation would execute thousands of chip updates per tick plus resampling and buffer writes; offline C speed cannot establish VM/YYC speed. Prefer a small C extension candidate after licensing clearance, then one isolated native microbenchmark. A pure GML backend is neither ruled out nor demonstrated necessary. No extension or benchmark was added to the POC.
